왜 WebSocket인가
Core Concept
HTTP는 요청-응답, WebSocket은 전화 통화
HTTP는 편지를 보내고 답장을 받는 구조입니다. 한 번 주고받으면 연결이 끊깁니다.
WebSocket은 전화를 걸어 연결이 유지된 상태에서 언제든 양방향으로 말할 수 있습니다.
게임처럼 실시간으로 데이터를 계속 주고받아야 할 때 WebSocket이 필요합니다.
HTTP (기존 방식)
클라이언트가 먼저 요청해야만 서버가 응답
요청-응답 1쌍이 끝나면 연결 종료
서버가 먼저 데이터를 보낼 수 없음
실시간 업데이트하려면 계속 폴링(반복 요청) 해야 함
헤더 오버헤드가 큼
WebSocket (실시간)
한 번 연결하면 계속 유지
서버 → 클라이언트 먼저 데이터 전송 가능
양방향 동시 통신
헤더 없이 작은 프레임으로 데이터 전송
지연시간(latency)이 매우 낮음
핵심 용어 정리
🔌 소켓 (Socket)
두 프로그램이 네트워크로 데이터를 주고받을 수 있는 연결 통로입니다. 수도관처럼 한 번 연결되면 데이터가 계속 흘러다닐 수 있습니다.
🌐 포트 (Port)
같은 컴퓨터 안에서 여러 서비스를 구분하는 번호입니다. 아파트 호수처럼 동일한 IP(건물)에서 3000번 방, 5900번 방처럼 구분합니다. WebSocket 서버는 보통 3000 또는 8080을 씁니다.
📦 프레임 (Frame)
WebSocket이 데이터를 전송하는 최소 단위입니다. 택배 박스처럼 데이터를 잘라서 프레임에 담아 보냅니다. 우리가 직접 신경 쓸 필요는 없고, 라이브러리가 자동으로 처리합니다.
🔄 이벤트 (Event)
WebSocket 프로그래밍은 이벤트 기반입니다. "연결됐을 때", "메시지 받았을 때", "연결 끊겼을 때"처럼 상황이 발생하면 미리 등록한 함수가 자동으로 실행됩니다.
🖥️ 서버 (Server)
항상 켜져 있으면서 클라이언트의 연결을 기다리는 프로그램입니다. 이 프로젝트에서는 Node.js (pygame-server)가 담당합니다.
📱 클라이언트 (Client)
서버에 연결을 시작하는 쪽입니다. 이 프로젝트에서는 Python 게임 (PyQt6)이 클라이언트입니다.

WebSocket 핸드셰이크
How It Works
처음 연결할 때만 HTTP를 씁니다
WebSocket은 HTTP로 시작해서 "이제부터 WebSocket으로 바꿔서 얘기하자"고 합의합니다. 이 과정을 핸드셰이크(Handshake)라고 합니다. 악수처럼 서로 확인하고 프로토콜을 전환합니다.
1
클라이언트 → 서버: HTTP 업그레이드 요청
클라이언트(Python)가 서버에 "HTTP 연결을 WebSocket으로 업그레이드해줘"라고 요청합니다.
GET /chat HTTP/1.1 Upgrade: websocket Connection: Upgrade Sec-WebSocket-Key: dGhlIHNhbXBsZQ==
2
서버 → 클라이언트: 101 Switching Protocols
서버가 "OK, WebSocket으로 바꾸자"고 승인합니다. 101은 "프로토콜 전환"을 의미합니다.
HTTP/1.1 101 Switching Protocols Upgrade: websocket Connection: Upgrade Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
3
연결 수립 — 이제부터 WebSocket
HTTP 연결이 WebSocket 연결로 업그레이드됩니다. 이 시점부터 양방향으로 자유롭게 메시지를 주고받을 수 있습니다.
🔗 연결 유지 (연결을 끊을 때까지 계속)
4
메시지 교환 (무제한)
서버와 클라이언트가 언제든 먼저 메시지를 보낼 수 있습니다. 연결을 명시적으로 닫을 때까지 유지됩니다.
client → server: {"type": "chat", "msg": "안녕"} server → client: {"type": "reply", "msg": "반가워"}
연결 상태 4가지
0 · CONNECTING 연결 중
핸드셰이크가 진행 중인 상태입니다. 아직 메시지를 보낼 수 없습니다.
1 · OPEN 연결됨
연결이 수립되어 메시지를 자유롭게 주고받을 수 있는 상태입니다. 대부분의 로직은 여기서 동작합니다.
2 · CLOSING 닫는 중
연결 종료 절차가 진행 중입니다. close 프레임을 주고받는 중입니다.
3 · CLOSED 닫힘
연결이 완전히 종료된 상태입니다. 다시 통신하려면 새로 연결해야 합니다.
이벤트와 연결: on_open → OPEN 상태, on_close → CLOSED 상태, on_message → OPEN 상태에서 메시지 수신 시 호출됩니다.

Node.js WebSocket Server
ws — 가장 가볍고 빠른 Node.js WebSocket 라이브러리
ws는 socket.io보다 단순하고 빠릅니다. socket.io는 자동 재연결, 룸 등 기능이 많지만 무겁습니다. 지금처럼 Python 클라이언트 하나와 통신한다면 ws가 딱 맞습니다.
# pygame-server 폴더에서 실행
npm install ws
기본 서버 코드
const WebSocket = require('ws');

// WebSocket 서버 생성 — 포트 3000에서 대기
const wss = new WebSocket.Server({ port: 3000 });

wss.on('connection', function(ws) {
    // 클라이언트가 연결됐을 때
    console.log('클라이언트 연결됨');

    ws.on('message', function(data) {
        // 클라이언트로부터 메시지 받았을 때
        const msg = JSON.parse(data);
        console.log('받음:', msg);

        // 클라이언트에게 응답 보내기
        ws.send(JSON.stringify({ type: 'reply', msg: '받았어!' }));
    });

    ws.on('close', function() {
        // 연결이 끊겼을 때
        console.log('클라이언트 연결 종료');
    });
});

console.log('서버 시작: ws://localhost:3000');
data.toString() 필수 (ws v8+): ws 최신 버전에서 message 이벤트의 data는 Buffer 타입입니다. JSON.parse(data)는 에러가 납니다. 반드시 JSON.parse(data.toString())을 쓰세요.
ws 파라미터 이름: wss는 서버 전체(WebSocket Server), ws는 연결된 개별 클라이언트 소켓입니다. 클라이언트마다 각자의 ws가 생깁니다.

websocket-client 설치
Python WebSocket Client
websocket-client — Python에서 WebSocket 연결
Python에서 WebSocket 서버에 접속하는 라이브러리입니다. 이벤트 콜백 방식으로 동작해서 Node.js의 .on('message')와 구조가 비슷합니다.
pip install websocket-client
기본 클라이언트 코드
import websocket
import json
import threading

def on_open(ws):
    # 연결됐을 때 — 서버에 첫 메시지 보내기
    ws.send(json.dumps({ "type": "hello", "msg": "안녕!" }))

def on_message(ws, message):
    # 서버로부터 메시지 받았을 때
    data = json.loads(message)
    print("받음:", data)

def on_error(ws, error):
    print("에러:", error)

def on_close(ws, code, msg):
    print("연결 종료")

ws = websocket.WebSocketApp(
    "ws://localhost:3000",
    on_open    = on_open,
    on_message = on_message,
    on_error   = on_error,
    on_close   = on_close
)

# run_forever() — 연결을 유지하며 이벤트를 기다림
# 별도 스레드에서 실행해야 PyQt6 UI가 멈추지 않음!
thread = threading.Thread(target=ws.run_forever)
thread.daemon = True
thread.start()
중요 — 스레드 분리 필수: ws.run_forever()는 블로킹 함수입니다. PyQt6 메인 스레드에서 그냥 실행하면 UI가 완전히 멈춥니다. 반드시 threading.Thread로 별도 스레드에서 실행하세요.
PyQt6와 통합하는 방법
from PyQt6.QtCore import QObject, pyqtSignal
import websocket, json, threading

class WSClient(QObject):
    # 시그널: WebSocket 스레드 → Qt 메인 스레드로 안전하게 전달
    message_received = pyqtSignal(dict)
    connected        = pyqtSignal()
    disconnected     = pyqtSignal()

    def __init__(self):
        super().__init__()
        self._ws = None

    def connect(self, url: str):
        self._ws = websocket.WebSocketApp(
            url,
            on_open    = lambda ws:        self.connected.emit(),
            on_message = lambda ws, m:   self.message_received.emit(json.loads(m)),
            on_close   = lambda ws, c, m: self.disconnected.emit(),
        )
        t = threading.Thread(target=self._ws.run_forever)
        t.daemon = True
        t.start()

    def send(self, data: dict):
        if self._ws:
            self._ws.send(json.dumps(data))

# 사용
client = WSClient()
client.message_received.connect(lambda data: print("서버에서:", data))
client.connect("ws://localhost:3000")
pyqtSignal이 핵심: WebSocket 콜백은 별도 스레드에서 실행됩니다. Qt UI를 다른 스레드에서 직접 건드리면 크래시가 납니다. Signal을 통하면 Qt가 자동으로 메인 스레드로 전달해줍니다.
자동 재연결 & 앱 종료 처리
# run_forever에 reconnect 옵션 — 끊기면 N초 후 자동 재연결
t = threading.Thread(
    target=self._ws.run_forever,
    kwargs={ "reconnect": 5 }  # 5초 후 재연결 시도
)
t.daemon = True
t.start()

# 앱 종료 시 WebSocket 정리 — main.py의 QApplication 종료 전에 호출
import atexit

def cleanup():
    if ws_client._ws:
        ws_client._ws.close()

atexit.register(cleanup)
reconnect=5 동작: 서버가 꺼져있거나 네트워크가 끊겨도 5초마다 재연결을 시도합니다. on_open 콜백이 재연결 성공 시 다시 호출되므로 거기서 초기화 로직을 처리하면 됩니다.

Message Design
JSON + type 필드로 모든 메시지를 구분한다
WebSocket은 그냥 문자열을 보냅니다. 어떤 종류의 메시지인지 구분하려면 포맷을 직접 정해야 합니다. 가장 많이 쓰이는 방법은 JSON에 type 필드를 넣는 것입니다.
// 좋은 예 — type 필드로 종류 구분
{ "type": "chat",   "msg": "안녕하세요", "from": "player" }
{ "type": "score",  "value": 95, "char_id": 0 }
{ "type": "ping" }
{ "type": "error",  "code": "NOT_FOUND" }
항상 JSON.stringify / json.dumps: WebSocket.send()는 문자열만 받습니다. 객체를 그냥 보내면 "[object Object]"가 됩니다. 반드시 JSON으로 직렬화하세요.
서버에서 type별로 분기 처리
// Node.js 서버
ws.on('message', (raw) => {
    const msg = JSON.parse(raw);

    switch (msg.type) {
        case 'chat':
            handleChat(ws, msg);
            break;
        case 'score':
            handleScore(ws, msg);
            break;
        case 'ping':
            ws.send(JSON.stringify({ type: 'pong' }));
            break;
        default:
            console.warn('알 수 없는 타입:', msg.type);
    }
});
# Python 클라이언트에서도 같은 방식
def on_message(ws, raw):
    msg = json.loads(raw)
    handlers = {
        'reply' : handle_reply,
        'score' : handle_score,
        'pong'  : lambda m: None,
    }
    handler = handlers.get(msg['type'])
    if handler:
        handler(msg)

서버에서 게임 상태 관리하기
// Node.js — 게임 상태를 메모리에서 관리
const gameState = {
    scores:    { 0: 50, 1: 50, 2: 50, 3: 50 },  // 캐릭터별 호감도
    respIndex: { 0: 0,  1: 0,  2: 0,  3: 0  },  // 대화 인덱스
    solved:    false,
};

function handleChat(ws, msg) {
    const id    = msg.char_id;
    const idx   = gameState.respIndex[id];
    const chars = require('./chars.js');  // config.py에 있던 데이터
    const [reply, delta] = chars[id].responses[idx];

    gameState.scores[id]    += delta;
    gameState.respIndex[id]  = (idx + 1) % chars[id].responses.length;

    ws.send(JSON.stringify({
        type:        'reply',
        char_id:     id,
        msg:         reply,
        score_delta: delta,
        score:       gameState.scores[id],
    }));
}
ping / pong — 연결 상태 확인
왜 ping/pong이 필요한가?
네트워크가 갑자기 끊겨도 소켓은 그 사실을 바로 모릅니다. 주기적으로 ping을 보내고 pong이 오지 않으면 연결이 끊긴 것으로 판단합니다. 
# Python — 10초마다 ping 보내기
import threading

def keep_alive(ws):
    while True:
        threading.Event().wait(10)
        ws.send(json.dumps({ "type": "ping" }))

# on_open에서 시작
def on_open(ws):
    t = threading.Thread(target=keep_alive, args=(ws,))
    t.daemon = True
    t.start()

Signal은 "뭔가 일어났다"는 알림이고, Slot은 그 알림을 받아 처리하는 함수입니다. .connect()로 Signal에 Slot을 연결합니다.

# 커스텀 시그널 정의
class ChatScreen(QWidget):
    message_sent = pyqtSignal(str)       # str 타입 데이터를 전달하는 시그널
    score_changed = pyqtSignal(int, int)  # int 두 개 전달 (char_id, delta)

    def _on_send(self):
        text = self.input.text()
        self.message_sent.emit(text)     # 시그널 발생 — 연결된 슬롯 호출됨

# 다른 곳에서 연결
chat.message_sent.connect(lambda msg: print("보냄:", msg))
chat.score_changed.connect(update_gauge)

class MyWidget(QWidget):

    def keyPressEvent(self, event):
        # 키를 눌렀을 때
        from PyQt6.QtCore import Qt
        if event.key() == Qt.Key.Key_Return:
            self._on_send()
        elif event.key() == Qt.Key.Key_Escape:
            self.go_back()

    def mousePressEvent(self, event):
        # 마우스 클릭
        if event.button() == Qt.MouseButton.LeftButton:
            print("클릭 위치:", event.pos())

    def resizeEvent(self, event):
        # 창 크기가 바뀔 때 — 이 게임에서 스케일 계산에 활용
        new_size = event.size()
        super().resizeEvent(event)  # 부모 메서드도 항상 호출!

class WSWorker(QThread):
    # 결과를 메인 스레드로 전달하는 시그널
    received = pyqtSignal(dict)

        ws = websocket.WebSocketApp("ws://localhost:3000", on_message=on_msg)

effect = QGraphicsOpacityEffect(widget)
widget.setGraphicsEffect(effect)

# 페이드인 애니메이션 (0.0 → 1.0 / 300ms)
anim = QPropertyAnimation(effect, b"opacity")
anim.setDuration(300)
anim.setStartValue(0.0)
anim.setEndValue(1.0)
anim.setEasingCurve(QEasingCurve.Type.OutCubic)
anim.start()

# 페이드아웃 후 숨기기
anim2 = QPropertyAnimation(effect, b"opacity")
anim2.setDuration(200)
anim2.setStartValue(1.0)
anim2.setEndValue(0.0)
anim2.finished.connect(widget.hide)
anim2.start()
b"opacity" 왜 bytes? QPropertyAnimation은 Qt C++ 내부 시스템을 쓰기 때문에 프로퍼티 이름을 bytes로 전달해야 합니다. Python str이 아닌 b"..." 리터럴을 씁니다.

자주 하는 실수 & 해결법
1
JSON.parse(data) → SyntaxError
ws v8+에서 data는 Buffer입니다. JSON.parse(data.toString())으로 고치세요.
2
UI가 완전히 멈춤
run_forever()를 메인 스레드에서 실행한 겁니다. threading.Thread로 분리하세요.
3
Qt UI 업데이트가 다른 스레드에서 크래시
WebSocket 콜백에서 직접 label.setText() 등 호출 금지. pyqtSignal.emit()으로 전달하세요.
4
Connection refused — 서버가 없다
Python 클라이언트보다 Node.js 서버를 먼저 실행하세요. 포트 번호도 확인.
5
[object Object] 가 전송됨
Node.js에서 JSON.stringify() 없이 객체를 send() 한 겁니다.
6
send() 했는데 메시지가 안 감
연결이 OPEN 상태인지 확인. ws.readyState === WebSocket.OPEN 체크 후 전송하세요.
7
QTimer.singleShot 안에서 변수가 None
람다 캡처 문제. lambda r=reply: self._show(r) 처럼 기본값으로 캡처하세요.
8
스크롤이 맨 아래로 안 감
위젯 추가 직후 maximum()이 아직 계산 안 됐습니다. QTimer.singleShot(50, scroll_to_bottom)으로 지연하세요.
